# 生源泉マップ 網羅調査の共通ルール

リポジトリ /Users/mon/Developer/NamaOnsen の data.json に、日帰りで入れる源泉かけ流しの温泉を地図用に集めている。
前回の調査はニフティ温泉の「源泉かけ流し」分類を主に拾ったため、漏れがある（例: 熊本市北区の梶尾温泉 https://onsen-life.com/facility/kajio-onsen が入っていない）。
今回は **担当地域の候補を漏れなく洗い出し、1軒ずつ判定する**。リポジトリのファイルは変更しない（data.json は読むだけ）。

## 1. 候補の洗い出し（ここが一番大事）
担当地域の日帰り入浴できる温泉施設を、次のすべてから集めて1つの候補リストにする。1つの情報源で済ませない。
- ニフティ温泉の県・エリア別一覧（かけ流し分類に限らず全部）
- onsen-life.com の県別一覧（熊本 https://onsen-life.com/prefecture/43 と /prefecture/43/higaeri-onsen、栃木 https://onsen-life.com/prefecture/9。ページ送りも全部）
- 純温泉協会 realonsen.com の県内認定施設
- 自治体・観光協会・温泉組合の施設一覧（例: 各温泉地の旅館組合・入湯手形の参加旅館、共同浴場の一覧）
- じゃらん・るるぶ・温泉ソムリエ系の「源泉かけ流し」記事、個人ブログの温泉地巡り記事、Google 検索「<市町村名> 源泉かけ流し 日帰り」
- 町の銭湯型温泉・共同浴場・公衆浴場（地元の小さな温泉が漏れやすい）

## 2. 判定
候補ごとに次のどれかを決める。
- **収録**: 日帰り可、全浴槽が源泉かけ流し（加水・加温は可）、営業中。循環ろ過の浴槽が1つでもあれば入れない。
- **除外**: 理由を一言（循環あり／日帰り不可／閉業／休業中／地元専用／かけ流しの根拠なし など）
- **保留**: 根拠が足りず判断できない（何が足りないか書く）
data.json にすでにある施設（id か名前・住所で照合）は「既収録」として候補リストに記録するだけでよい。ただし閉業・日帰り終了・循環ありなど既収録の間違いを見つけたら、報告に書く。

## 3. 収録する項目の書き方
data.json の既存項目（例: id "kikuchi-shironoi"、id "onsen001086"）にキーと書き方を合わせる:
id（ニフティにあれば onsenNNNNNN、なければ英小文字とハイフン）, name, prefecture, address, lat, lng, kakenagashi, chlorine（"なし（公式）"|"なし（口コミ）"|"不明"|"あり"）, kasuiKaon, hasSauna（"あり"|"なし"。蒸し湯も「あり」）, sauna, mizuburo, hours, closed, price, tel, url（必須。公式がなければニフティや onsen-life の施設ページ）, evidence（"- " で始まる行、[表示名](URL) のリンクと確認日つき）, caveats, checkedAt: "2026-11-01"。わからない任意項目は省く。
- 塩素: 公式・浴室掲示・純温泉協会の「消毒なし」なら「なし（公式）」、口コミ・ブログなら「なし（口コミ）」、塩素を使うとはっきりしていれば「あり」、根拠なし・割れていれば「不明」。推測で「なし」にしない。
- かけ流しの根拠が onsen-life やニフティの分類だけのときは、kakenagashi にそう書き、caveats で「浴槽ごとの確認はしていない」と書く（既存項目と同じ）。
- 座標: 国土地理院の住所検索 https://msearch.gsi.go.jp/address-search/AddressSearch?q=... や OpenStreetMap で確かめる。ニフティ等の座標が役場・温泉地の代表点になっていないか確認する。
- **外部サービスへのリクエストにメールアドレスなどの個人情報（User-Agent・クエリ・ヘッダー）を一切入れない。** 汎用の User-Agent を使う。

## 4. 出力
作業ファイルは scratchpad/<担当名>/ の中だけ（他の担当も同じ scratchpad を使う）。（クラウド実行では出力先は research/cloud/<担当名>/）
- scratchpad/<担当名>.json: 新たに収録する項目の配列
- scratchpad/<担当名>-checked.json: 候補リスト全件の配列。各要素 {name, address, source: [見つけた情報源], verdict: "収録"|"除外"|"保留"|"既収録", reason, id}
最後に報告: 候補の総数と情報源ごとの件数、収録・除外・保留・既収録の件数、新規収録の塩素区分の内訳、保留の一覧、既収録の誤りの疑い。
