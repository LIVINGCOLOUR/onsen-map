# 既収録の温泉の「今も営業しているか・情報が古くないか」の確認

かけ流し日帰りマップ（data.json）に載っている温泉が、2026-11-05 時点で今も日帰り入浴を受けているか、営業時間・料金・定休日などが変わっていないかを確かめる。
まず research/brief/common.md を読み、塩素の基準・個人情報の決まりに従う。

## 対象
research/cloud/freshness/<担当名>-targets.json の全件（id, name, address, url, hours, closed, price, tel, chlorine, hasSauna, caveats, checkedAt）。

## 1件ずつ確かめること
1. **営業しているか**: 公式サイト（お知らせ・営業案内の下層まで）、自治体・観光協会のページ、ニフティ温泉の施設ページ（閉館表示・最新の口コミの日付）、Google の検索結果の「閉業」表示、最近（2025〜2026年）の口コミ・ブログ。
2. **日帰り入浴を今も受けているか**: 宿の場合は特に。休止・宿泊者のみに変わっていないか。
3. **営業時間・定休日・料金**: 公式（なければ自治体・ニフティ）の今の値と data.json の値を比べる。
4. **湯の使い方が変わっていないか**: 循環ろ過・塩素の導入、源泉の変更などがわかったら記録（かけ流しでなくなっていれば削除の候補）。
5. 塩素は、新しい一次情報（公式・掲示の写真・はっきりした口コミ）があるときだけ変える。

## 判定の基準
- **削除**: 閉館・廃業・日帰り入浴の終了・かけ流しでなくなったことが、公式・自治体・報道、または日付つきの複数の口コミではっきりしているもの。
- **休業中（再開予定あり・長期休業）**: 削除せず、caveats の先頭に「【休業中】…（いつから・再開予定・根拠）」を書く。
- **修正**: 時間・料金・定休日・電話・URL が変わっていれば set で直す。caveats を set するときは既存の文を含めた全文を書く。
- **問題なし**: updates には入れない（checked には書く）。
- **わからない**: 公式が見つからず口コミも古いもの → checked に「保留」として書き、call.md に電話番号と聞くことを書く。

## 守ること
- data.json と index.html は変更しない（読むだけ）。git の commit・push はしない。
- 外部へのリクエストに個人情報を入れない。汎用の User-Agent。有料のものは使わない。
- 1つのサイトへは1秒以上あけて読む。WebSearch は多くても25回、一覧や公式は curl で直接読む。

## 出力（research/cloud/freshness/<担当名>/）
- updates.json: [{id, name, set:{...}, evidenceAdd:"- 2026-11-05 確認: …（URL）", reason}]、削除は {id, name, delete:true, reason}（reason に根拠のURLと日付）
- checked.json: 対象全件 {id, name, verdict: "問題なし"|"修正"|"休業中"|"削除"|"保留", reason, source}
- call.md: 保留の施設名・電話・聞くこと
- report.md: 件数の内訳、削除・休業中の一覧と根拠、注意点、使った検索回数
